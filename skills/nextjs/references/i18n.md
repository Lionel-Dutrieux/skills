# i18n

next-intl, the same files in every project. With one language, keep `request.ts` and
`messages/` only; the rest comes with the second language.

## The files

```
messages/en.json  messages/fr.json   the words, one namespace per feature
src/i18n/routing.ts                  the locales
src/i18n/navigation.ts               the internal links
src/i18n/request.ts                  locale, messages, time zone per request
src/global.d.ts                      the types of the messages and the locales
```

```ts
// src/i18n/routing.ts
import { defineRouting } from 'next-intl/routing'

export const routing = defineRouting({ defaultLocale: 'en', locales: ['en', 'fr'] })

export type Locale = (typeof routing.locales)[number]
```

```ts
// src/i18n/navigation.ts
import { createNavigation } from 'next-intl/navigation'

import { routing } from './routing'

export const { Link, redirect, usePathname, useRouter } = createNavigation(routing)
```

Internal links use this `Link`, not `next/link`: it keeps the locale.

```ts
// src/i18n/request.ts
import { hasLocale } from 'next-intl'
import { getRequestConfig } from 'next-intl/server'

import { routing } from './routing'

export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale
  const locale = hasLocale(routing.locales, requested) ? requested : routing.defaultLocale

  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default,
    timeZone: 'Europe/Brussels',
  }
})
```

With the `translations` plugin, `messages` comes from its `getMessages`, which lays what
editors approved over the file: its `llms.md` shows the call.

## Typed messages

```ts
// src/global.d.ts
import type messages from '../messages/en.json'
import type { routing } from './i18n/routing'

declare module 'next-intl' {
  interface AppConfig {
    Locale: (typeof routing.locales)[number]
    Messages: typeof messages
  }
}
```

`t('posts.title')` is then checked: a key missing from `en.json`, or misspelled, fails
`tsc`. The other locales are checked by a test, since a type only sees one file.

```ts
// tests/unit/messages.unit.spec.ts
import { describe, expect, it } from 'vitest'

import en from '../../messages/en.json'
import fr from '../../messages/fr.json'

type Tree = { [key: string]: string | Tree }

const entries = (tree: Tree, prefix = ''): [string, string][] =>
  Object.entries(tree).flatMap(([key, value]) =>
    typeof value === 'string' ? [[`${prefix}${key}`, value]] : entries(value, `${prefix}${key}.`),
  )

/** The ICU arguments and tags of a message: `{count}`, `<link>`. */
const placeholders = (message: string) =>
  [...message.matchAll(/\{\s*(\w+)|<(\w+)>/g)].map(([, arg, tag]) => arg ?? tag).sort()

describe('the messages', () => {
  it('have the same keys and placeholders in every locale', () => {
    const reference = new Map(entries(en))

    for (const [key, message] of entries(fr)) {
      expect(reference.has(key), key).toBe(true)
      expect(placeholders(message), key).toEqual(placeholders(reference.get(key) ?? ''))
    }
    expect(entries(fr).length).toBe(reference.size)
  })
})
```

## Keys

- One top-level namespace per feature, named like its folder: `posts`, `contact-form`.
  `common` for what several features share (`common.save`).
- A component takes its namespace: `useTranslations('posts')`, `getTranslations('posts')`
  in a Server Component.
- The key says what the text is, not where it sits: `posts.emptyList`, not `posts.text3`.
- Plurals and variables are ICU in the message (`{count, plural, one {# post} other {# posts}}`),
  never assembled in code.

## Adding a language

1. Add it to `routing.ts` (and to Payload's `localization.locales` when the content is
   localized too).
2. Copy `messages/en.json` to `messages/<locale>.json` and translate it.
3. The messages test tells you what is missing.
